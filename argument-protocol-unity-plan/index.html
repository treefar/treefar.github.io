一句話：不從 HTML 反抽任何東西。資產全在 Generated/、敘事資料全在 resolved-story.json、行為真值全被 47 個測試鎖死——移植就是「重寫殼、照搬料、對同一份考卷」。

為什麼要移：HTML 單檔 156.84 MiB 已超 GitHub 上限，Firefox 記憶體超 1,500 MiB 硬門檻且無降載空間；瀏覽器單檔路線的天花板已到。Unity 沒有這兩個限制，還能一次解掉 BGM 循環、資產串流與發行通路問題。

2. 三個支點（為什麼移植成本可控）

  1. 資產不用抽：Generated/ 保有全部原始檔——84 張 PNG（含切格規則可由樣板推得）、6 首 OST 的 master.wav＋stems、157 句語音 MP3＋口型時間軸（mouthCues）、4 套 WOFF2。
  2. 資料不用寫：Generated/resolved-story.json（schema 4）就是完整敘事資料庫：cases／profiles／interludes／interludeChoices／interludePerformances／narrativeArcs／chapterEpilogues，一支匯入器就能進 Unity。
  3. 驗收不用想：47 個 spec 早已把行為鎖成可判定條件（例：探索完成後 routeHistory=0,1,0,2,3、返程成本 5 秒、CASE 00 三題關係語意為 反證/反證/時序）。Unity 版拿同一份考卷來考。

3. 硬規則（發給任何執行者的工單都要抄進第 0 節）

版本鎖：Unity 一律 6000.5.10f1（四台統一基準，開工先跑 unity-version-guard）；禁止降版、禁止用更新版開啟。
範圍鎖：副戰力只做「執行」不做「設計」；一律獨立 branch；同一檔案同一時間只交一個工具；工單必附白名單目錄與 yes/no 驗收條件。
美術鎖：只搬運既有 84 張核准影像；任何新美術仍走核准生圖管線（AGY／Codex／ImageGen），程式產生的像素只能當 graybox。264 格章間動畫缺口不因移植消失。
音訊鎖：循環音樂一律用 Generated/music/*/master.wav（WAV 無編碼縫隙，Unity AudioSource.loop 天生無縫）；不要拿 master.mp3。
權利鎖：157 句語音是 Edge TTS／System.Speech 產物，公開散布權未封板——Unity 版預設「語音功能做好但先關」，權利解決前不得隨遊戲公開發布。

8. 風險與已知缺口

解析度策略要先定：HTML 版是 canvas 無級縮放；Unity 需定 reference resolution（建議 1280×720）與 390×844 直式安全區。這是 WP3 開工前的設計決策，屬主力工作。
座標翻譯是最大陷阱：HTML 的 UI 全是 canvas 座標寫死；照抄數字必錯。工單要求以「比例＋錨點」重寫，驗收看行為不看座標。
語音權利未封板：見權利鎖。M1 展示版可用字幕＋音效走完流程。
美術 264 格缺口照舊：31 個章間 beat 只有 11 個完整；移植不會讓它變完整，M2 之後仍要回頭補生。
